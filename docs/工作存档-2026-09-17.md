## 一、问题回顾

管理员点击「完成」活动后，**所有报名用户都没有收到积分**。前端 UI 显示"已完成"，但数据库 `status` 字段没变化。

### 三个根因（连锁）

1. **`autoFinish` 查询 bug**
   `cloudfunctions/getActivities/index.js` 第 46 行：
   ```js
   // 错误写法：_.exists(true).and(_.lt(now)) 链式调用在云开发里被静默忽略
   .where({ status: 'active', timeEnd: _.exists(true).and(_.lt(now)) }).get()
   ```
   **根因**：`timeEnd` 在数据库中是**字符串类型**（`"2026-07-01T12:00:00.000Z"`），而 `_.lt(new Date())` 与字符串不能比较。所以 `autoFinish` 永远扫不到过期活动。
   **修复**：用 `_.lt(new Date().toISOString())` 做字符串字典序比较。

2. **`finishActivity` 三处缺陷**
   - 循环里**没有 try/catch**：一个 userId 异常导致全员不发分
   - **没有幂等保护**：手动 finish + 定时器 autoFinish 重复触发，会重复发分
   - **覆盖式 update**：`points: balance` 而非 `_.inc(delta)`，并发场景丢分
   **修复**：每个用户独立 try/catch；按 `rewarded:true` 标记去重；用 `_.inc()` 原子自增。

3. **前端 `computeState` 与 DB status 解耦**
   `computeState` 在 `timeEnd < now` 时直接显示「已完成」，但**没回写 DB**。
   这导致管理员看到 UI 是「已完成」就以为系统处理了，实际上 status 仍是 `'active'`。
   **修复**：依赖后端定时器真正去归位状态。

## 二、一次性补发云函数 `fixActivityPoints`

新建 `cloudfunctions/fixActivityPoints/`，用于历史数据补发。

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `dryRun` | `true` | 只统计不发分（先看影响面） |
| `activityId` | — | 只处理指定活动 |
| `since` | — | 只处理 finish 时间晚于该值 |
| `force` | `false` | 强制补发（无视 rewarded 标记，慎用） |
| `limit` | `50` | 单批处理上限 |
| `activityIndex` | `0` | 分批续跑索引 |
| `statusList` | `['finished']` | 自定义 status 过滤 |
| `queryAll` | `false` | 调试模式：忽略 status 过滤 |
| `cleanupStale` | `false` | 把 status='active' 且 timeEnd 已过的活动改成 'finished' |

### 幂等保证
- 通过 `activity_registrations.rewarded` 字段标记
- 不带 `force` 时，已发过（`rewarded=true`）的报名自动跳过
- 流水 `points_records.source='fixActivityPoints'` 区分正常发分

### 实际执行
- 扫描 5 条历史活动，22 个报名，12 个待补发
- 全部 awarded=12，failed=0
- 之后跑 `cleanupStale:true` 把 5 条 status='active' 归位为 'finished'

## 三、定时触发器

`cloudfunctions/getActivities/config.json`：
```json
{
  "triggers": [
    { "name": "autoFinishActivitySweep", "type": "timer", "config": "0 0 3 * * * *" }
  ]
}
```

- 每天 03:00 自动跑 `autoFinish()`
- 不依赖用户访问页面
- 也支持手动触发：`wx.cloud.callFunction({ data: { autoFinishSweep: true } })`

### 2. 发布活动时间默认值调整

| 字段 | 旧默认 | 新默认 |
|---|---|---|
| 开始 | 今天 07:00 | **当前时刻** |
| 结束 | 今天 +2h（09:00） | **明天同一时刻** |
| 截止 | 今天 -1h（06:00） | **结束 -1h** |

**联动逻辑同步更新**：`onDate` 里改开始时间时，结束自动 +24h，截止自动 =结束-1h。

### 3. 活动广场可见性修复

**问题**：用户清理完历史活动后，活动广场选"全部状态"也看不到任何活动。

**根因**：`getActivities` 的 `list` action 过滤 `status='active'`，但所有活动都改成 `'finished'` 了。

**修复**：`list` 不再过滤 status，由前端按 `stateTag.text` + `filterIdx` 筛选。

```js
// cloudfunctions/getActivities/index.js
// 修改前：
const query = db.collection('activities').where({ status: 'active' }).orderBy('timeStart', 'asc');
// 修改后：
const query = db.collection('activities').orderBy('timeStart', 'asc');
```
