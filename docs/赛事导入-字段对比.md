# 赛事导入 - 表格字段 vs race_events 字段对比

> 数据源：腾讯文档《国内路跑认证赛事》智能表格导出（2027/2026/2025/2024H2/2024H1，共 1164 条）
> 目标：用表格数据生成 race_events 草稿，替换质量较差的网页爬取数据（raceAutoFetch）

---

## 一、可直接映射（表格 → 现有字段）

| 表格字段 | 现有字段 | 转换说明 |
|---|---|---|
| 赛事 / 赛事名称 | `name` + `raceGroup` | name=赛事名+年份（如 北京马拉松2026）；raceGroup=去掉年份（北京马拉松）。年份取比赛日期所在年 |
| 比赛日期 / 开赛日期 | `date` | 转 Date |
| 省份 | `province` | 直接使用 |
| 比赛项目 | `raceTypes` | 全程→full、半程→half、10km→10k；中距离/短距离忽略（现有无枚举） |
| 总规模 | `scale` | 数字 |
| 报名费 | `fee` | 原文（如 US$90/85/70） |
| 官网 | `website` | URL |
| 报名开启时间 | `timeline`[报名开启] | {label, date, time} |
| 报名截止时间 | `timeline`[报名截止] | 同上 |
| 出签日期 | `timeline`[出签时间] | 同上 |
| 缴费时间 | `timeline`[缴费截止] | 同上 |
| 状态 | `status` | 已结束→finished；待确定/报名中/待开赛/待出签/待报名→upcoming；取消/推迟/熔断→待确认 |
| 抽签 | `mechanism` | ✔️→抽签；❌→先到先得 |

## 三、现有模型有、表格没有（导入留空/默认，管理员补）

- `city` 城市：表格只有省份+起点，可尝试从起点/名称推断，或留空
- `distance` 距离、`elevation` 爬升：留空
- `posters` 海报、`certs`(itra/utmb/utmbws)、`gunTimes`、`tagsStr`、`description`：留空
- `payment` 缴费方式：可从抽签推断（抽签→中签后缴费，先到先得→先缴费），或留空

## 四、表格有、导入忽略

- 创建时间、最后编辑时间（用户确认不需要；系统用 createTime/updateTime 自管）

## 五、字段值归一化（需确认）

### 1. 赛事等级 raceLevel + label
- 表格各年份体系不同：2024 用 A1/A2/B类/A类/AIMS；2025/2026 用 A/B/认证中/标牌/精英/金标/AIMS/WA
- 建议：含 A/A1 → raceLevel=A；含 B → B；其余（AIMS/认证中/标牌/WA）→ C 或留空
- label：金标→金标；精英→精英标；标牌→普通标；白金标→白金标（可选）
- ❓ 需要确认这套映射

### 2. 状态 status
- 已结束→finished；其余→upcoming
- 取消/推迟/熔断：现有模型只有 upcoming/finished，❓是否新增 status=cancelled 还是忽略

### 3. 比赛项目 raceTypes
- 全程→full、半程→half、10km→10k
- 2024 年表大量「中距离/短距离」，❓忽略还是映射到 10k

### 4. 去重
- 同一年份同名赛事 → 以 name 去重（建草稿时若同名已存在则跳过/更新）
- 跨年份同名 → raceGroup 归组（复用现有"同组赛事"能力）

## 六、导入方式建议

- 新增导入脚本/云函数：读 CSV → 标准化 → 写入 `race_events` 草稿（`publishStatus=draft`, `source=table`）
- 支持 `dryRun` 预览：将新建 N 条、跳过 M 条（同名已存在）
- 导入后可在赛事管理「草稿」页签审核发布
